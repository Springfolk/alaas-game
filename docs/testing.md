# Testing

- No unit tests; verification is `npm run lint` (undefined/unused names), `npm run build` and headless checks against `npm run dev`.
- Tools launch system Chrome (`CHROME` overrides the path) or Playwright WebKit via `tools/browser.mjs`; `PORT` picks the dev server. npm scripts: `shot`, `walkcheck`, `hitch`, `loadprof`, `bench` (args after `--`).
- `node tools/shot.mjs "/?auto&at=x,z,yaw" out.png 1280 720 4000` — system Chrome headless with WebGPU (`playwright-core` dev dependency); never takes the screen. Waits for `game.sharp` (textures at the tier size). Prints the backend and console errors. `DPR=2|3` sets the pixel ratio (also `bench`).
- `EVAL="js"` (or `SCRIPT=file`) runs code in the page before the shot (`window.game`, `window.viewer`); its console warnings print, each line once.
- Models: `viewer.html?m=<model>&cam=x,y,z&look=x,y,z`; it sets `window.ready` after 40 frames.
- Pointer lock can't be granted headless; `?auto` starts without it.
- Safari: test with Playwright's WebKit (`npx playwright-core install webkit`, then `webkit.launch()`); it has WebGPU. Safari builds shaders far slower than Chrome.
- Load stages log to the console: `ground`, `homestead`, `nature/<module>: N ms`, `warm-up: …`.
- Loading: `node tools/loadprof.mjs [chrome|webkit|phone] [query] [shotPrefix]` (first world pixel, playable, main-thread stalls before and 2.5 s after; `THROTTLE=4`: CPU ×4; shots at 1/2/4/8 s) · `node tools/walkcheck.mjs [chrome|webkit|phone]` (shaders/pipelines built on a walk: must be 0/0; `EARLY=1` starts at ready: no frame >50 ms). Both take `PORT`. After changing a model or tree: `npm run bake-impostors` (`docs/loading.md`).
- Phone: Chrome context `{390×844, deviceScaleFactor 3, isMobile, hasTouch}`; drive the stick/look with CDP `Input.dispatchTouchEvent` (multi-touch), buttons with `page.touchscreen.tap`. Keyboard play headless: set `game.input.locked = true`, add codes to `game.input.keys`.
- Performance: `node tools/bench.mjs [chrome|webkit|phone] [query]` (uncapped; `?gputime` turns on GPU timestamp queries — summed per pass, overcounts on Apple GPUs, compare only relatively). Phone emulation with an iPhone UA or `isMobile`+touch auto-picks the `mobile` tier. Hitches: `node tools/hitch.mjs [chrome|webkit|phone]` (headless WebKit's rAF runs at ~77 Hz, so 13 ms there is the 60 cap working).
- Smoothness: `node tools/smooth.mjs [chrome|webkit|phone|lite] [query]` — at the game's own pacing, per area (18) × stand/walk/run/turn: drawn-frame interval p50/p95/p99/max from rAF timestamps, dips (interval > 1.5× the paced one) with what the frame did, JS ms, `gpu` (ms from the end of the frame's JS until the GPU finished it: latency, ≈7 ms at any load, near the paced interval = frames queueing), Chrome also garbage per frame and collections. `lite` = phone reporting 2 GB. Env: `THROTTLE=4` (CPU ×4), `AREAS`, `MOVES`, `SECS`, `SIZE=1728x1117@2` (a Retina laptop), `JSON=file`; `LAT=1` look latency (age of the look events when the frame's JS ends, how far the view trails the aim; driven events arrive a frame late headless, WebKit's mouse moves carry no movement); `COST=1` uncapped ms per frame at every area in 12 directions (`RES=1` full resolution, `WHY=n` what the n worst spend it on). Dips are rare events: run it alone on the machine, repeat a cell that dips.
- Pacing logic without a browser: `node tools/pace-sim.mjs [name]` runs `src/engine/pacing.js` against modelled devices (fast, GPU-bound, CPU-bound, a heavy view, phones at 30, 60–240 Hz displays with timestamp jitter): fps, dips in all and in the last third, resolution range and changes, knobs, input→display. Rerun after touching `pacing.js`: the last third must stay at 0 dips.
- Load breakdown: `node tools/loadtrace.mjs [chrome|webkit] [query] [profile.json]` (dev or `vite preview` on `PORT`; `?prof`: main-thread ms per stage and bucket, worker/pipeline spans, resources; Chrome adds a CPU profile; `AFTER=1` the 2.5 s after ready). Compare variants in alternating runs: timings drift over minutes.
- Shader builds: `node tools/shaders.mjs [chrome|webkit] [query] [out.json]` (per pass/material, main-thread build time; `TOP=n` slowest; `COVERED=1` the key-art load) · `?nomaster` turns off master materials (`docs/materials.md`).
- `?nomerge` turns off shadow merging, impostors and size culling (A/B screenshots).
- iOS Simulator (real Mobile Safari; no WebGPU there, the Mac's GPU): `xcrun simctl boot <id>`, then `SIM=1 node tools/iphone.mjs …` — first stop for iOS bugs.
- Real iPhone over USB (Safari › Advanced › Remote Automation; `safaridriver -p 4723`): `node tools/iphone.mjs spots|ab|play|load "<query>" …` — uncapped ms/frame with JS and GPU-fence ms per spot; interleaved runtime A/B (`SEQ=` exact order, `hide:`/`mat:`/`light:` toggles); the game's own pacing while turning (fps per 5 s); boot marks and bytes. On WebGL2 it switches between a slow (~45 ms) and a fast (~17 ms) state; any lighter moment (`blank 0.5s`, a hidden model, a shader build) kicks it fast for ~8 s, so compare only within one state (`SEQ`, draw counts in brackets).
- Mac GPU (same Apple GPU family, no state flips): `node tools/gpuab.mjs "<query>|<query>" [spots] [toggles]`: phone tier on WebGL2 at an iPhone's pixel count, median GPU ms (timer query; ~0.7 ms floor) and JS ms per frame. `node tools/jsprof.mjs [query] [x,z,yaw] [s]` — CPU profile of play, ms per frame by file and function.
- Real phone: serve a build on the tailnet (`npx vite preview --port 5199` + `tailscale serve --bg --https=8443 http://127.0.0.1:5199`; set `__VITE_ADDITIONAL_SERVER_ALLOWED_HOSTS` to the ts.net name, WebGPU needs HTTPS), open with `?remotelog`, and run `node tools/phonelog.mjs` mounted at `/__log` (`tailscale serve … --set-path /__log http://127.0.0.1:5200`): console, errors and a 2 s heartbeat (frames, rendered, longest gap, `cpu` = JS ms per frame, `gpu` = ms until a WebGL2 fence after a frame signals — high gpu with low cpu: GPU-bound; tier, resolution, audio state).
- `?perftest` (on a device, via `?remotelog`): at each bench spot (start, yard, inside, lake, forest edge) uncapped fps with one layer hidden at a time (grass, flowers, forest, homestead, frozen shadows) and the frame's triangles/draws.
